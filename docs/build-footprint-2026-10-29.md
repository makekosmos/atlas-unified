# Atlas build footprint and crate inventory

Snapshot: 2026-10-29. Source checkout: `codex/unified-gpui`, commit `6e0f3b6`; the Cargo manifests and Rust sources were unchanged during the measured compile. The dependency lists include normal and build dependencies, with duplicate versions retained. They come from `cargo tree --locked --edges normal,build`; Android is the separate `android/rust` workspace, whose `engine-mobile` dependency is pinned in its lockfile.

## Release bundles

| Platform | Published `v0.0.1` artifact | Size | Contents / dominant files |
| --- | --- | ---: | --- |
| Windows x86_64 | `Atlas-Setup.exe` | 21,538,916 bytes (20.5 MiB) | NSIS installer; installs one `atlas.exe`, creates an uninstaller and Start Menu shortcut, and writes the uninstall registry entry (`scripts/atlas.nsi`). |
| macOS Apple Silicon | `Atlas.dmg` | 19,015,812 bytes (18.1 MiB) | Disk image containing `Atlas.app`; local rebuild from this checkout produced a 26,991,259-byte DMG and a 59 MiB app bundle (56 MiB executable, 2.6 MiB icon). |
| Android ARM64 | `Atlas-Android-arm64.apk` | 42,066,664 bytes (40.1 MiB) | APK has 23 entries, all native libraries under `arm64-v8a`; expanded payload is 42,997,019 bytes. |

Android APK largest entries (uncompressed sizes from the published APK):

- `lib/arm64-v8a/libnsh.so`: 24,705,560 bytes (57.5% of expanded APK).
- `lib/arm64-v8a/libatlas_mobile.so`: 15,118,952 bytes (35.2%); Rust mobile library statically links the pinned `engine-mobile` dependency.
- `lib/arm64-v8a/libc++_shared.so`: 1,292,904 bytes.
- `assets/nsh/bundle.nshc`: 632,271 bytes; `classes.dex`: 534,352 bytes; JS bundle and source map together: 486,594 bytes.

Android is therefore dominated by native code, not the TSX bundle. The AAR carries multiple ABIs, while Gradle filters the application to `arm64-v8a`, so only that ABI lands in the APK.

## Build time and working space

One local macOS ARM64 release compile was measured with a fresh `CARGO_TARGET_DIR`, while the machine’s Cargo registry and Git source caches were already warm. `cargo build --locked --release --bin atlas --target aarch64-apple-darwin --timings` ran from **2026-10-29 14:09:44 UTC to 14:15:18 UTC: 334 seconds**. The isolated target directory reached **2.2 GiB**. The next build against that target ran **2026-10-29 14:16:34–14:16:39 UTC: 5 seconds**; Cargo recompiled the Atlas crate, and reused the dependencies. This is one cold/warm pair, not a five-run performance study.

The Mac had 8 logical cores and load averages 1.69 / 1.90 / 2.14 before the run. `time -lp` reported 1,932 seconds user CPU, 76 seconds system CPU, 0 swap, and 1.7 GiB maximum RSS. The Cargo report’s longest individual units were `gpui-fast` 180.71 s, `nsh-base` 149.75 s, `gpui-pre` 140.47 s, `gpui-component` 137.85 s, `gpui-base` 135.32 s, `quickjs-jit-stdlib` 120.22 s, and `nsh-core` 111.21 s. These unit times overlap across parallel compiler jobs; do not sum them as wall time.

The complete interactive Cargo timings report for the cold compile is [`cargo-timing-macos-cold.html`](cargo-timing-macos-cold.html). It contains all 821 Cargo units, their durations, dependency waits, and codegen phases.

Cargo home at the time of the snapshot occupied about **10.1 GiB**: registry sources/cache/index 3.4 GiB and Git checkouts 6.7 GiB. The largest entry was the NSH source checkout at 6.0 GiB, of which **5.9 GiB is its ignored `target/` cache**: 4.9 GiB debug, 692 MiB Android target, 300 MiB release, 26 MiB NSH Android output. This is cached build output nested in Cargo’s Git checkout; it is not the Atlas application binary. The 2.2 GiB isolated target used for this audit is temporary and is removed after recording the report.

Cold and warm builds for Windows, macOS, and Android are instrumented in [`.github/workflows/build-metrics.yml`](../.github/workflows/build-metrics.yml). On its run summary it records UTC start/end to the second, download and build seconds, Cargo/Gradle cache sizes, target sizes, and final artifact bytes. That workflow has not yet run in GitHub for this branch; Windows and Android timings below are therefore pending runner evidence.
